# Сохранённые расчёты для каталога РФ

## Модель хранения

`public.russia_price_snapshots` хранит один текущий снимок на активное объявление, источник и назначение. История пересчётов не создаётся. Снимок содержит результат TKS и коммерческий расчёт в одном JSON-объекте, статус, дату успешного расчёта и дату следующей попытки. При ошибке последний успешный JSON не удаляется; в строке обновляется только короткий код ошибки и время повтора.

Таблица закрыта для `anon` и `authenticated`; серверный сайт и фоновая задача читают/пишут её через service role. Триггеры ставят строку в очередь при публикации, снятии с публикации или изменении входных полей. При снятии объявления снимок удаляется. Счётчик `revision` защищает от сохранения расчёта, если данные объявления изменились во время вызова внешнего API.

## Фоновый пересчёт

Команда: `npm run pricing:refresh-russia`.

По умолчанию за один запуск обрабатывается до 100 строк с параллельностью 4. Успешный снимок назначается на повтор через 24 часа. Временная ошибка повторяется через 30 минут, ограничение API — через 60 минут. Настройки можно менять через `RUSSIA_PRICE_BATCH_SIZE` (1–100) и `RUSSIA_PRICE_CONCURRENCY` (1–4). Запуск не пишет строки по каждому автомобилю: stdout содержит только агрегированный счётчик статусов и коды ошибок.

Systemd примеры: `ops/russia-price-refresh.service.example`, `ops/russia-price-refresh.timer.example`, `ops/russia-price-refresh.env.example`. Таймер запускает задачу каждые пять минут; systemd не запускает второй экземпляр того же oneshot-сервиса, пока первый ещё работает. На Mac mini LaunchAgent-loop берёт следующую партию через две минуты после завершения предыдущей.

## Безопасный rollout

1. Создать миграцию для price snapshots в Supabase после проверки SQL на staging/копии базы.
2. Установить на worker-хост новые server-only секреты `VEHICLE_POWER_RESOLVE_TOKEN` и `VEHICLE_POWER_TKS_TOKEN`, а также Supabase service-role. Значения не помещать в репозиторий или журналы.
3. Применить миграцию: она создаёт компактную очередь для уже опубликованных объявлений; каталог пока может продолжить старое чтение.
4. Развернуть фоновую задачу и дождаться, пока начальная очередь заполнит успешными снимками активные объявления. Проверять агрегированные числа и `status`, без выборки токенов или payload.
5. Развернуть сайт, который читает российские цены только из снимков. Последний успешный снимок остаётся доступен во время сбоя пересчёта.
6. Сверить покрытие активного каталога и включить штатное расписание.

Миграция и worker подготовлены локально. Применение миграции, установка systemd и production deployment требуют отдельного rollout на целевом окружении; этот документ сам по себе не выполняет эти действия.
