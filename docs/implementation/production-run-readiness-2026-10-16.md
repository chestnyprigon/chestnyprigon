# Готовность Mac mini к следующему прогону

Проверено 16 октября 2026 на Mac mini. Новый массовый поиск и обогащение не запускались.

## Рабочая конфигурация

- Транспорт следующего запуска — `direct`, домашняя сеть. Транспорт должен быть явно сохранён в run и передан launcher; отсутствие значения останавливает запуск до любых Encar-запросов. Неявного переключения на proxy нет.
- Обычное обогащение: одна машина одновременно; техническая пачка — до 10; задержка политики — 10 секунд; до 3 endpoint-попыток. Размер технической пачки не меняет сохранённый состав волн.
- Перед новым запуском фиксируются фактический объём кандидатов, список ID и равномерный план волн. Worker проходит все сохранённые волны; лимит отдельного старого вызова на 50 не завершает такой run.
- Screening завершённой волны выполняется отдельно от обогащения следующей. Публикация требует отдельного подтверждения владельца.
- `caffeinate` удерживает Mac mini от автоматического сна во время worker. Экран можно блокировать, терминал можно закрывать. LaunchAgent не зависит от открытого терминала.
- Глобальная DB lease и локальная блокировка защищают от второго enrichment worker. Старые approved/paused очереди не выбираются для старта самостоятельно: нужен явный run/связанная задача.

## Исправления по итогам проверки

1. Launcher и local worker требуют явный транспорт; coordinator отклоняет run с незаписанным транспортом. Preflight показывает сохранённые волны и область обработки вместо устаревшего универсального лимита 50.
2. Добавлен отдельный `--direct-network-check-only`: один GET поиска, без записи в БД, claim очереди, авторизации parser IP или публикации. Проверка блокируется при активной worker lease.
3. Telegram coordinator использует `publish-screened-cohort.ts`: полный screening, неизменяемый файл состава с checksum, DB manifest, блоки по 10, per-card результат и сверка публичности. При повторном выполнении используется исходный файл состава; новый screening не заменяет частично опубликованную партию остатком.
4. Исправлен SQL FULL JOIN в регистрации manifest: перед сравнением строки ограничены текущим manifest. Миграция `20261016150000_scope_publication_roster_comparison.sql` применена через SQL Editor Supabase; проверка определения функции вернула `roster_scoped_to_manifest=true`.
5. Отчёт Telegram сверяет старые партии без сохранённого roster через `encar_raw_listings.import_run_id` и фактические `vehicles.is_public`. Статус и отчёт подтверждают 26 публичных карточек последнего пилота; этап отображается как «публикация завершена».

## Выполненные проверки

- Один direct GET поиска Encar: корректный JSON, один результат, без proxy credential/dispatcher и без записи данных.
- Обе macOS LaunchAgent установлены, plist валидны и совпадают с репозиторием. Период координатора — 15 секунд. Сон компьютера в macOS отключён; добавлена дополнительная локальная защита на время worker.
- Нет активной DB lease, сохранённого `active-run` или ожидающих Telegram-команд. Транспорт состояния — `direct`.
- Таблицы волн и manifest доступны; OPTIONS для RPC волн, worker lock, команд и публикационных manifest вернул HTTP 200. Это проверка доступности RPC, а не выполнение записи.
- Telegram webhook настроен на `chestnyprigon.com/api/telegram/catalog-webhook`, очередь обновлений пуста. В истории есть старый HTTP 500; отсутствие нового сбоя проверено локальным вызовом текущего handler с production read-only данными. Сам внешний POST с production webhook secret не выполнялся: секрета нет в локальном окружении.
- `/catalog_status`, `/catalog_report`, `/catalog_plan` текущего handler возвращают HTTP 200 на production данных. Статус и отчёт сверены на 26 публикациях. Вызов handler не отправлял сообщений в Telegram и не создавал команды.
- В отдельной временной PostgreSQL проверены миграция, две независимые партии, идемпотентное повторение и отказ при подмене canonical ID. Production карточки для тестов не создавались.
- Unit-проверки охватывают отсутствие неявного сетевого маршрута, полный roster на 500 ID, восстановление неизменяемого roster, checksum, блокировки и классификацию endpoint-ошибок.

## Что остаётся наблюдать в реальном запуске

- Устойчивость домашней сети и отсутствие Encar ограничений на длительном объёме: один успешный запрос не гарантирует отсутствие будущих 403/429/CAPTCHA.
- Восстановление после фактической перезагрузки Mac mini и публикация нескольких новых DB manifest в production: подтверждены локально, но искусственно на production не запускались.
- Legacy catalog launch сохраняет DB-ограничения квот; обычный отдельный run использует рекомендации brand mix. Для очереди с `catalogLaunchId` публикатор заранее проверяет остатки квот и не выдаёт успех при превышении.

Новый массовый run создаётся после согласования его объёма. Тестовые и исторические очереди не являются новым набором кандидатов.
