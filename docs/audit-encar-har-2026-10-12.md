# Проверка свежих HAR Encar — 12 октября 2026

Источники: `/Users/koreakim/Downloads/17www.encar.com.har` (693 записи) и `/Users/koreakim/Downloads/1210encar.com.har` (172 записи). Проверка выполнена по сохранённым запросам и телам ответов, без сетевых запросов и изменений БД. Cookies, токены, персональные данные продавца и полные тела ответов сюда не перенесены.

## Поиск и причина предыдущей ошибки

В первом HAR все 20 запросов `/search/car/list/general` и 14 запросов `/search/car/list/premium` получили HTTP 200. Из 20 general-ответов 6 являются метаданными (`Count`, `iNav`), 14 — списками (`Count`, `SearchResults`). Запрос с `inav=|Metadata|Sort` закономерно не содержит `SearchResults`; это не свидетельство CAPTCHA или блокировки.

Успешные запросы списков используют:

- `Origin: https://www.encar.com`, `Referer: https://www.encar.com/`;
- `Accept: application/json, text/javascript, */*; q=0.01`;
- сортировку `sr=|ModifiedDate|0|8` и следующую страницу `|ModifiedDate|8|8`;
- реальные корейские названия марок, например `현대`, `기아`;
- для отечественных автомобилей `CarType.Y`; общий интерфейс также использует `CarType.A`;
- без заголовков `Authorization` и `Cookie` на этих API-запросах.

Пример фактического q: `(And.(And.Hidden.N._.(C.CarType.Y._.Manufacturer.기아.))_.AdType.A.)`. После отдельной проверки тот же фильтр `AdType.A` с дополнительными Year/Mileage ограничениями вернул корректный список.

В нашем `prepare-vps-live-queue.ts` Origin/Referer установлены на `fem.encar.com`, Accept отличается, размер страницы — 500; состав q включает год и пробег. Основной скрипт переводит Audi в `아우디` через таблицу aliases. Однако отдельный предыдущий диагностический запрос использовал `Manufacturer.Audi`, что не воспроизводило запрос основного скрипта.

HAR не содержит `/international/communication/validate-request-ip` или `/pass/user/verify`. Это показывает, что в записанном браузерном сценарии таких вызовов нет, но не доказывает отсутствие ранее установленного состояния доступа. Предыдущее утверждение, что пропущенная verification была установленной причиной ошибки, не подтверждено.

`fetch failed / Request was cancelled` из Mac mini не содержит ответа HTTP и не устанавливает виновника: транспорт, прокси или источник. HAR относится к успешной браузерной сессии и сам по себе не доказывает доступность того же маршрута через Decodo. Различия заголовков, q и размера страницы до сетевой проверки были гипотезами.

Следующая диагностическая проверка: один фактический GET списка из HAR на Mac mini через сохранённый Decodo, с записью этапа, времени, HTTP-статуса, формы ответа и цепочки сетевой ошибки. Запись кандидатов и worker для этой проверки не нужны. При успехе параметры менять по одному: общая секция списка, марка, год/пробег, размер страницы. Verification проверять отдельно, чтобы её ошибка не выдавалась за ошибку поиска. Cookies и токены браузерной сессии не переносить.

## Полнота карточки 42182499

Главные данные карточки находятся в HTML `fem.encar.com/cars/detail/42182499`, в JSON `__PRELOADED_STATE__.cars.base`. Сохранённый `requestUrl` указывает на серверный запрос:

`/v1/readside/vehicle/42182499?include=ADVERTISEMENT,CATEGORY,CONDITION,CONTACT,MANAGE,OPTIONS,PHOTOS,SPEC,PARTNERSHIP,CENTER,VIEW`

Это серверный путь из состояния HTML, а не отдельный запрос браузера в HAR. В основной карточке 26 фотографий, 33 кода штатных опций; присутствуют категория, характеристики, объявление и `condition` с информацией об осмотре, ДТП, арестах и залогах.

| Данные | Источник в HAR | Что делает текущий worker |
|---|---|---|
| Основная карточка, фото, штатные опции | Серверные данные в HTML; singular `/v1/readside/vehicle/{id}` с include | Запрашивает plural `/v1/readside/vehicles?vehicleIds=...`, включая OPTIONS. Полная эквивалентность singular/plural этим HAR не доказана |
| Аресты и залоги | `condition.seizing`, оба счётчика в примере равны 0 | CONDITION отсутствует в явном include основного запроса; получение этих полей не гарантировано |
| Дополнительные платные опции | `/v1/readside/vehicles/car/{id}/options/choice`, 3 записи | Endpoint уже используется |
| Осмотр | `/v1/readside/inspection/vehicle/{id}`, HTTP 200 | Endpoint совпадает |
| Диагностика | `/v1/readside/diagnosis/vehicle/{id}`, HTTP 200 | Endpoint совпадает |
| Страховые случаи и история владения | `/v1/readside/record/vehicle/{id}/open?vehicleNo=...`, HTTP 200 | Endpoint совпадает; номер должен соответствовать проверенному canonical ID |
| Описание продавца | `/v1/readside/vehicle/{id}?include=CONTENTS`, HTTP 200 | Отдельного запроса CONTENTS в данном worker нет |
| Selling points и фотографии опций | `/v1/readside/diagnosis/vehicle/{id}/sellingpoint`, HTTP 200 | Отдельного запроса в данном worker нет |
| Доступность resume | `/v1/vehicle/resume/valid`, `available:true` | Проверяется. Сам `/v1/vehicle/resume` в HAR не записан, его доступность/полнота не доказана |

`/options/choice` возвращает дополнительные заводские пакеты: в примере шторки/боковые подушки с датчиком опрокидывания, навигация DMB II и панорамный люк. Пустой choice не означает отсутствие штатного оборудования. Текущий `resolveEquipment` уже учитывает `detail.options.standard` и дополнительные choice; оснований возвращаться к обязательному непустому choice нет.

`/v1/readside/vehicles` в HAR относится к пяти рекомендованным автомобилям, а не к основной карточке. OPTIONS не включён в его query, и `options:null` здесь закономерен. Такой ответ нельзя использовать как доказательство отсутствия оборудования у основной карточки.

Для полноты текущего worker нужны гарантированное получение CONDITION, сохранение CONTENTS и sellingpoint, проверка штатных опций основного detail. Проверка canonical ID и принадлежности дополнительных ответов должна сохраняться. PUT счётчика просмотров, POST индикатора рекламы, запросы рекламы и рекомендации для обогащения не нужны.

## Статус

Этот аудит подтверждает структуру успешных запросов и два конкретных пробела полноты (CONDITION и CONTENTS; sellingpoint также не собирается). Точная причина сетевого отменённого запроса Mac mini пока не установлена. Массовый поиск, обогащение и публикация в ходе аудита не запускались.

## Безопасные пробы квотного поиска через Mac mini

12 октября дополнительно проверены страницы размера 500 через Decodo `kr.decodo.com:10001`; все пробы запускались одноразовым LaunchAgent в графическом сеансе, без записи в БД:

- Kia, `CarType.A` и текущие Year/Mileage: 500 результатов, `Count=4986`;
- Audi, `CarType.A`: 325 результатов, `Count=325`; тот же запрос с `CarType.Y` дал 0 — для квотного запроса выбран широкий `CarType.A`;
- Chevrolet с точным API-именем `쉐보레(GM대우)`: `Count=606`;
- Renault Korea с точным API-именем `르노코리아(삼성)`: `Count=524`;
- общий `CarType.A` вернул 19 471 результат и включает импортные и корейские марки; общий `CarType.Y` — 12 943 и только корейские марки в первой странице.
- Три варианта имени Mazda (`마쯔다`, `마쓰다`, `마츠다`) при действующих фильтрах вернули `Count=0`; в отчёте поиска квота Mazda будет помечена как недоступная по текущей выдаче, без подмены другой маркой.

Это подтвердило два исправления для подготовки поиска: использовать широкий `CarType.A` вместе с проверенными `AdType.A`, заголовками HAR и псевдонимами марок; при сетевых сбоях или 5xx повторять только ту же страницу до трёх попыток, а на 403/429 останавливать весь поиск без записи кандидатов. Хранилище дубликатов проверяется до сетевых запросов. Готовая очередь создаётся со статусом `awaiting_approval`, поэтому worker не может начать обогащение до отдельного решения владельца.
