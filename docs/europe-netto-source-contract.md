# Контракт цены Netto для европейского каталога

Статус: локальная подготовка, 6 ноября 2026 года. Production и постоянные базы не изменялись.

## Цена

Для каталога и калькулятора используется Netto из структурированных данных объявления Mobile.de: `price.nt.amount`. Brutto находится отдельно в `price.grs.amount`. Берём готовое Netto из источника; не пересчитываем его из Brutto.

Аудит пяти объявлений подтвердил, что исходное Netto уже записано в `master.listing_price_observations.reported_net_amount` и локальное `cars.price_net`; Master API просто не выводит его в каталожный ответ. API-проекция `net_price` нужна только для передачи уже существующего `reported_net_amount` сайту; отдельное значение цены не создаётся.

В прошлой проверке значения `cars.price_net` совпадали с `gross / 1.19`, из-за чего я ошибочно решил, что это вычисленная цена. Разбор парсера и сверка пяти объявлений показали, что значение извлекалось из `price.nt.amount`; совпадение суммы с арифметическим расчётом не меняет её происхождение.

Ожидаемый объект внутреннего API:

```json
{
  "price": { "amount": 0, "currency": "EUR", "type": "original_asking" },
  "net_price": {
    "amount": 0,
    "currency": "EUR",
    "basis": "netto",
    "status": "source_reported",
    "source_path": "price.nt.amount",
    "source_observed_at": "ISO-8601 timestamp"
  }
}
```

Пример показывает формат, не реальное значение. Если Netto отсутствует, объявление не включается в каталог с расчётом. Расчёт цены под ключ остаётся предварительным.

## Первая регистрация

Для фильтра каталога и возрастной категории предварительного расчёта используется первая регистрация из объявления. Отдельное поле даты изготовления не требуется.

## Что подготовлено

- Локальный сборщик извлекает только `price.nt.amount` и не вычисляет Netto из Brutto.
- В изолированной ветке Master Core подготовлена передача существующего `reported_net_amount` в API-объекте `net_price`. Это дополнительное поле ответа с тем же Netto, а не новая цена. Миграция локальная и не применялась.
- В Chestny Prigon цена в карточках, на главной и в калькуляторе берётся только из `net_price`, подтверждённого путём `price.nt.amount` и статусом `source_reported`. Brutto не используется как запасной вариант. В локальном калькуляторе возраст определяется только по первой регистрации, а расчёт явно предварительный.
- Европа читает отдельную версию Supabase-представления `mobile_de_catalog_turnkey_v2`; существующая выдача и Корея не переключались.

## Остаётся сделать

Вывести существующий `reported_net_amount` из Master API под отдельным ключом `net_price`, затем повторить read-only dry-run небольшой партии и сверить расчёты. `net_price` — только имя поля API; сумма уже хранится в Master DB. До сквозной проверки не переключать production.
