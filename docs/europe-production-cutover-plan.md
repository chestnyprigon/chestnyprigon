# План локальной реализации и переноса европейского каталога

Актуальная сверка от 6 ноября 2026 года. Базовая Europe-выборка уже импортирована в существующий Supabase и отображалась в Vercel Preview. Production-сайт не переключался. Сейчас завершается Netto-калькулятор и готовится отдельный Europe-only production cutover; Корею не менять.

## Согласованная логика

- Каталог показывает только объявления под заданные фильтры: первая регистрация 2022–2025, мощность не выше 160 л. с., пробег не выше 100 000 км, категории цены mobile.de `Sehr guter Preis`, `Guter Preis`, `Fairer Preis`.
- Объявления без даты первой регистрации, включая `Neuwagen`, исключаются.
- Для цены используется только Netto из объявления Mobile.de (`price.nt.amount`), уже сохранённое в Master DB как `reported_net_amount`. Брутто не пересчитывается.
- Предварительный расчёт для физического лица идёт до Минска. Возрастная категория для расчёта определяется по первой регистрации. Отдельное поле даты изготовления не требуется.
- Курс EUR/BYN берётся из действующего источника НБРБ. Льготный режим включён по умолчанию и переключается пользователем.

## Что показала проверка источника

- Проверка парсера и пяти объявлений подтвердила, что `price_net` извлекался из исходного `price.nt.amount` и уже хранится в Master DB `reported_net_amount`. Совпадение суммы с `gross / 1.19` не означает, что она была вычислена.
- Текущий detail-ответ Master API показывает Brutto в `price.amount`, но не проецирует существующий `reported_net_amount`.
- Локальный патч в worktree `codex/europe-netto-calculator` добавляет эту проекцию в API. Миграция не применена.
- Локальная read-only проверка импортёра на 3 allowlist-записях не записывала данные: 0 принято, 3 пропущено, потому что текущий API не отдаёт уже существующий Netto. Это ограничение проекции API, не отсутствие цены в источнике или базе.
- Отдельная локальная проверка на трёх ранее сверенных образцах дала Netto €27 722,69 / €22 592,44 / €21 504,20 и приняла 3/3. Она использовала fixture-ответы и не доказывает, что настроенный API сейчас отдаёт Netto.
- Предварительные результаты калькулятора по курсу НБРБ 3,3599 BYN/EUR на 06.11.2026: €27 722,69 → 130 637,77 BYN с льготой и 152 992,66 BYN без неё; €22 592,44 → 108 567,76 / 126 785,74 BYN; €21 504,20 → 104 563,22 / 122 580,69 BYN. Все три первых регистрации попадают в возрастную категорию до 3 лет на дату расчёта.
- Целевой API-тест M-DE-22 в изолированном Master Core прошёл: 2/2. Соседний исторический интеграционный тест M-DE-06 не проходит независимо от патча: он ссылается на неподдерживаемый scope `catalog:audit` и ожидает скрытия отключённого источника, которого текущий тестовый API-контракт не обеспечивает. Права API ради этого теста не менялись.
- После исправления пути `price.nt.amount` прошли профильные проверки: collector/adapter 4/4, M-DE-06 нормализатор/адаптер 5/5, M-DE-22 API 2/2, калькулятор Беларуси 3/3; TypeScript проверка сайта прошла. SQL-представление проверено на одноразовой тестовой БД и база уничтожена после проверки.

## Результат проверки тарифов (06.11.2026)

- Приложение 2 к Решению Совета ЕЭК №107 подтверждает пошлины для легковых автомобилей по стоимостным порогам до 3 лет и по объёму двигателя для категорий 3–5 и старше 5 лет. Граничные проверки включения пороговых значений и перехода в следующий диапазон проходят.
- Постановление Совета Министров Беларуси №195 действует с 29.04.2026. Для легкового автомобиля, ввозимого физлицом для личного пользования, приложение 2, подпункт 1.3 устанавливает ставки 624,92 BYN для авто до 3 лет включительно и 1 282,02 BYN для авто старше 3 лет. МНС подтверждает применение постановления №195 с указанной даты.
- Указ №140 — не всеобщая скидка: 50% возмещения распространяются на определённые категории физлиц, постоянно проживающих в Беларуси, для автомобиля для личного пользования. Утильсбор остаётся полным. UI сохраняет включённый по умолчанию переключатель согласно согласованному плану и разъясняет необходимость подтверждённого права.
- Возрастные категории тарифов по нормам зависят от даты выпуска, но калькулятор использует первую регистрацию из объявления по согласованному продуктовому требованию. Интерфейс помечает это как предварительную оценку; при оформлении возраст сверяют с документами автомобиля.
- Проверка калькулятора в браузере на локальном route прошла на desktop и ширине 390 px: три карточки используют ранее сверенные Netto €27 722,69 / €22 592,44 / €21 504,20; detail показывает расчёт и переключатель пересчитывает пошлину и итог. Утильсбор при переключении не меняется. Тест `npm run test:pricing` — 19/19, TypeScript — без ошибок. Проверка изображений в браузере зависит от доступности хоста Mobile.de.

## Результат изолированной проверки SQL (06.11.2026)

- Черновая схема применена к одноразовому локальному PostgreSQL, без подключения к Supabase и постоянным базам.
- В наборе из 5 строк опубликованная turnkey view вернула ровно 3 машины с актуальным, подтверждённым Netto. Контрольная запись с несовпадающей исходной ценой и запись без одобрения исключены.
- Проверены диапазон Netto €22 000–23 000, пробег ≤ 6 000 км, мощность ≤ 120 PS и объём ≥ 1 900 см³; каждый фильтр вернул ожидаемое число строк. Facets вернули марки, модели после выбора марки, типы топлива/коробки/кузова и диапазоны.
- Галерея выдала все 4 тестовых фото. Роль anon читает только каталоговую view и facets; прямое чтение таблицы price evidence отклонено.
- Тестовый откат выполнен через транзакцию: исходные таблицы и публичные представления сохранились, новые объекты восстановились после `ROLLBACK`.
- Одноразовая SQL-проверка нового v2 draft подтвердила фильтры и права на искусственной выборке. Она не заменяет уже существующий импорт 7 333 строк в Supabase; новый v2 view на постоянном Supabase отсутствует.
- Настроенный Master API дал 0/3 Netto в read-only dry-run. Записей в Supabase этим запуском не выполнялось.
- Локальный Core API-патч в отдельной ветке прошёл M-DE-22 (2/2) и точечные проверки нормализатора; опубликованный API не менялся. Соседний полный M-DE-06 integration test остановился до HTTP-проверки с `API_CONFIG_INVALID` из-за исторического scope `catalog:audit`; права API этим не менялись.

## Что реально осталось до Production

1. Завершить одну цепочку Netto: локальная Core API-проекция → dry-run 3/3 из живого API → добавить Netto к существующим 7 333 строкам Supabase без повторного импорта объявлений и фото → проверить count/filter/detail/calculator в Vercel Preview. Сейчас настроен только `https://api.koredigital.co.kr`; отдельного Preview Master API нет. Применение подготовленной проекции требует изменения Master API production-сервиса, поэтому это отдельный блокирующий этап и не выполняется без отдельного подтверждения.
2. Подготовить узкий релиз для Production. Ветка каталога опережает `main` на 54 коммита; перед переносом нужен список Europe-only/shared изменений и проверка, что Корея не меняется. Не сливать автоматически всю ветку.
3. Сделать Production deploy только после Preview-проверки и отдельного подтверждения пользователя; заранее сохранить текущие настройки и точные действия отката.

Не повторять полный импорт 7 333 объявлений, повторные тесты фильтров на искусственной базе или пересоздание таблиц без причины. В существующей базе уже есть нужные объявления и галереи; незакрытый блокер — Netto и подключение калькулятора.
