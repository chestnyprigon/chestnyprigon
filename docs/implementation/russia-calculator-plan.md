# План внедрения расчёта для РФ

Статус: согласован пользователем. Вести строго по этапам: перед каждым следующим этапом проверить критерии текущего checkpoint. Не переходить дальше, пока все критерии не выполнены на 100% и результат не отражён в этом файле.

## Принципы

- Существующий расчёт Беларуси не переписывать и не менять его результат при выборе РФ.
- Российский официальный ТКС держать отдельным расчётным профилем и вызывать через Vehicle Power API.
- Разделять государственные платежи и коммерческие затраты. Внутренне сохранять валюты, версии правил и происхождение данных; в каталоге показывать цену в RUB без поясняющего текста об источниках и допущениях.
- Для каждого объявления формировать предварительный расчёт. Сначала использовать совместимые сохранённые данные; если их недостаточно, сервером запросить Vehicle Power и выбрать наиболее подходящую предварительную мощность. Не оставлять карточку без цены только из-за отсутствия точного документального значения.
- Не запускать массовые записи/миграции и не менять production-данные без отдельного обоснования. Предпочитать расчёт при открытии карточки с коротким кэшированием и фиксированным снапшотом результата для заявки.
- По умолчанию сайт сохраняет текущий рынок/маршрут Беларусь; выбор страны назначения задаётся один раз на уровне сайта и сохраняется между каталогами и карточками.

## Checkpoint 0 — аудит исходного состояния

Статус: **ВЫПОЛНЕНО** (2026-11-07).

- В проекте Vehicle Power существует `POST /v1/tks/calculate`, доступный только с bearer scope `tks:calculate`.
- Локальная документация Vehicle Power описывает расчёт duty/STP excise/VAT/recycling/utilization/customs processing; коммерческие расходы туда не входят.
- TKS требует цену с валютой, дату регистрации или модельный год, объём (если применимо), тип силовой установки, корректную базу мощности и происхождение/уверенность.
- EV и последовательные гибриды требуют electric 30-minute power; параллельные гибриды — мощность ДВС плюс electric 30-minute. Peak/system не подменяют эти значения.
- В «Честном пригоне» найден действующий расчётный профиль Беларуси; отдельной реализации РФ и общего переключателя направления пока нет.
- В `.env.local` есть `VEHICLE_POWER_API_BASE_URL` и `VEHICLE_POWER_RESOLVE_TOKEN`. Безопасная проверка вызова TKS с resolve-токеном вернула HTTP 401; это не токен scope `tks:calculate`.
- Код и базы в ходе аудита не менялись.

## Checkpoint 1 — отдельный TKS consumer-токен

Статус: **ВЫПОЛНЕНО** (2026-11-07).

Что требуется:

1. В операторском окружении проекта Vehicle Power выпустить отдельный consumer с именем, например, `chestny-prigon-tks` и единственным scope `tks:calculate`.
2. Штатная команда из репозитория Vehicle Power: `npm run consumer:create -- --name chestny-prigon-tks --scope tks:calculate`. Команда использует операторский `VEHICLE_POWER_PROVISIONER_DATABASE_URL`, а не runtime-секрет API.
3. Bearer показывается при выпуске один раз. Сохранить его сразу как серверный секрет `VEHICLE_POWER_TKS_TOKEN` в локальном `.env.local` проекта «Честный пригон» и в Vercel (Production; Preview/Development — только если там будет проверяться TKS). Не присылать токен в чат, коммит, браузер или клиентские переменные `NEXT_PUBLIC_*`.
4. Сверить, что `VEHICLE_POWER_API_BASE_URL=https://power.koredigital.co.kr` задан на сервере.
5. Проверить новый токен запросом к `/v1/tks/calculate`: пустое тело должно пройти аутентификацию и завершиться ожидаемым HTTP 400 (`invalid_request`), а не 401. Затем сделать контролируемый расчёт на тестовом сценарии; не включать токен `power:resolve` в права TKS consumer.

Критерий 100%: локальная и production-конфигурации содержат секрет под именем `VEHICLE_POWER_TKS_TOKEN`; scope проверен HTTP-ответом; тестовый запрос с валидным тестовым автомобилем возвращает версию правил, RUB rates и breakdown; секрет нигде не выведен и не записан в git.

Проверка checkpoint 1:

- Пользователь подтвердил, что `VEHICLE_POWER_TKS_TOKEN` добавлен в `.env.local` и Vercel. В локальном файле наличие проверено без вывода значения. Vercel CLI/привязки проекта в этой рабочей среде нет, поэтому Vercel-настройка зафиксирована по подтверждению пользователя.
- Запрос `{}` в production Vehicle Power endpoint `/v1/tks/calculate` с новым токеном вернул HTTP 400 `invalid_request` (а не 401): аутентификация и scope приняты.
- Контролируемый тест для ДВС вернул HTTP 200, движок `koredigital-tks`, версию `koredigital-ru-individual-tks-2026.06` и полный breakdown. В запрос передан явно фиктивный официальный-rate fixture (KRW 0.05, USD 80, EUR 90, KZT 0.15), чтобы не зависеть от текущих ставок и не сохранять rate snapshot; суммы этого теста не являются ценовым предложением.
- Токен и его значение нигде не выводились. В исходниках и базах «Честного пригона» изменений не делалось.
- Переменная Vercel начнёт использоваться приложением только после будущего deployment с интеграционным кодом; текущую production-сборку ради неиспользуемой переменной перевыпускать не требуется.

После checkpoint записать дату/среду/статус без самого токена. До этого checkpoint не переходить к интеграции endpoint.

## Checkpoint 2 — утвердить режим российского ввоза и правила ТКС

Статус: **ВЫПОЛНЕНО** (2026-11-07; расчётная методика согласована пользователем как предварительная).

1. **Режим подтверждён пользователем 2026-11-07:** физическое лицо, ввоз для личного пользования. Первая версия сайта поддерживает этот сценарий.
2. Сверить текущие версии duty, STP excise/VAT, утилизационного сбора, таможенного сбора и правил даты/возраста с первичными официальными источниками РФ/ЕАЭС.
3. Зафиксировать дату действия правил, границы сценариев и известные ограничения. Сверить результаты Vehicle Power с утверждёнными контрольными примерами TL Auto/TKS для ДВС, EV, HEV/PHEV и возрастных границ.

Результаты проверки официальных источников и локального кода, а также согласованные правила предварительного расчёта (2026-11-07):

- Утилизационный сбор для M1 изменён ПП РФ № 1713 с 01.12.2025; ФНС сообщает, что учитывается мощность в кВт, для физлица сохраняются льготные значения только при выполнении условий (в частности, порог мощности 160 л. с.; для EV/последовательных гибридов отдельный порог 80 л. с.; для непоследовательного гибрида берётся суммарная мощность). Сверка с кодом Vehicle Power показывает, что он уже использует отдельные kW-границы и компонентный расчёт мощности, но сам TKS endpoint не принимает признак типа импортёра/личного пользования и выбирает льготную колонку по мощности/возрасту автоматически.
- С 01.01.2026 основная ставка НДС РФ составляет 22% по ФЗ № 425-ФЗ; TKS движок использует 22% в ветке STP для EV/последовательных гибридов.
- Уточнение после чтения полного текста ПП РФ № 1637: пункт 5 действительно задаёт 689 RUB для общего случая личного ввоза, **но пункт 6 отдельно отсылает автомобили из категорий приложения № 2 к Решению ЕЭК № 107 к стоимостным ставкам пункта 1**. Поэтому диапазоны `customsProcessingFeeRub` в Vehicle Power могут быть корректны для соответствующих автомобилей. На checkpoint 2 всё равно надо зафиксировать классификацию/категорию ТС и доказать, какой пункт применим к каждому поддерживаемому сценарию; простого сопоставления названия тарифа недостаточно.
- Ветка **СТП для чистого EV** подтверждается таблицей 2 приложения № 2 Решения ЕЭК № 107: автомобили с исключительно электрическими двигателями идут через совокупный таможенный платёж, а не обычные единые ставки по объёму ДВС. Для EV код Vehicle Power считает 15% пошлины, акциз по мощности и 22% НДС; формулы и границы акциза скопированы из TL Auto. Для последовательного гибрида ветка выбрана по расчётной логике Vehicle Power, однако отдельный официальный источник, подтверждающий ту же классификацию для всех моделей/вариантов последовательных гибридов, в ходе этой проверки не найден. Классификация должна зависеть от кода ТН ВЭД/документов, а не только от внутреннего `powertrain`.
- Таблица 2 Решения № 107 прямо говорит: обычные легковые автомобили 8703 (кроме специально вынесенных категорий) облагаются едиными ставками по стоимости/возрасту/объёму; для чистых EV (8703 80 000) — СТП. Локальный код соответствует этим веткам для ICE/EV; параллельные гибриды считаются через ДВС-объёмные ставки и утильсбор по сумме применимых компонент мощности.
- **Согласованное приближение возраста:** пользователь подтвердил, что для предварительных сумм берём дату первой регистрации вместо даты выпуска; если точной даты первой регистрации нет — используем модельный год. Сохраняем окно оформления +30 дней и возрастные тарифные ветки Vehicle Power. Это осознанная методика предварительной оценки, не блокирующая покрытие каталога.
- Таможенный сбор: кодовые стоимостные диапазоны в `TKS_CUSTOMS_FEE_BANDS` (1 231–73 860 RUB) соответствуют опубликованным ставкам ПП № 1637/1638 для рассматриваемых легковых ТС. Пункт 6 ПП № 1637 отсылает перечисленные автомобили к тарифам пункта 1; ставка 689 RUB из пункта 5 не является универсальной ставкой для легковых автомобилей. Финальную привязку нужно хранить с классификационным условием.
- Утильсбор: ФНС подтверждает пороги 160 л.с. для ДВС/непоследовательных гибридов, 80 л.с. для EV/последовательных гибридов и суммирование мощности двигателей у непоследовательного гибрида. Используем реализацию Vehicle Power: соответствующую таблицу по типу силовой установки, доступным значениям мощности, объёму и возрасту. В рамках предварительной оценки не запрашиваем дополнительные документы импортёра и не оставляем карточку без расчёта из-за отсутствия такой проверки.
- Последовательные гибриды по согласованной логике Vehicle Power/TL Auto направляются в СТП-ветку вместе с EV; для СТП используется электрическая мощность. Параллельные гибриды остаются в ветке расчёта по ДВС, а утильсбор учитывает сумму компонентов согласно правилам Vehicle Power.
- **Требование к охвату:** каждый автомобиль каталога должен получить предварительную общую цену в RUB. Сначала используются сохранённые в проекте данные мощности/силовой установки; при недостатке входов серверный интеграционный слой использует Vehicle Power lookup/resolve и наиболее подходящее имеющееся предварительное значение. Источники, уверенность и допущения можно хранить внутри результата для трассировки, но не показывать в карточках каталога как поясняющий текст. Не допускать пустой цены только из-за отсутствия точной документальной мощности.
- Локальная проверка Vehicle Power: `npx tsx --test tests/tks-parity.test.ts` — 3/3 теста прошли; `npx tsx --test tests/tks-golden.test.ts tests/tks-governance.test.ts` — 3/3 прошли. Восемь frozen golden cases сверяют Vehicle Power и TL Auto по пяти строкам платежей и возрастному переходу; это подтверждает программную паритетность, но не является независимой юридической экспертизой ставок. Контрольные входы используют fixture-курсы и явные даты, не live-расчёты.
- Источники: [ФНС о новых правилах утильсбора и мощностных границах](https://www.nalog.gov.ru/rn60/news/activities_fts/16590008/), [ФНС о применении кВт по ПП № 1713](https://www.nalog.gov.ru/rn77/about_fts/about_nalog/16602625/), [ФНС о ставке НДС 22% с 2026 года](https://www.nalog.gov.ru/html/sites/www.rn61.nalog.ru/ufns/11176.pdf), [таблица 2 приложения № 2 Решения ЕЭК № 107 (редакция от 24.02.2026)](https://www.consultant.ru/document/cons_doc_LAW_293595/494cc0ed2f6860c75ac5bf4f7afbcee6f6795fbb/), [ПП РФ № 1637 в редакции ПП № 1638](https://www.consultant.ru/document/cons_doc_LAW_491874/92d969e26a4326c5d02fa79b8f9cf4994ee5633b/), [ЦБ РФ: официальный ежедневный XML курсов](https://www.cbr.ru/development/SXML/).

## Checkpoint 3 — коммерческий профиль «Корея → РФ» и «Европа → РФ»

Статус: **ВЫПОЛНЕНО** (2026-11-07). Профили и детерминированные контрольные примеры зафиксированы в [russia-commercial-profile-baseline.md](russia-commercial-profile-baseline.md). Это предварительная версия, отделённая от профиля РБ.

Разделить на самостоятельные строки:

- цена автомобиля и валюта источника;
- стоянка/оформление в Корее;
- логистика до РФ (с возможностью региона назначения);
- комиссия/наценка;
- услуги компании;
- расходы в РФ, не входящие в официальный ТКС;
- коммерческий курс KRW→RUB либо EUR→RUB/валюта цены;
- официальный курс ЦБ РФ для таможенной оценки — отдельно от коммерческого курса.

Для корейского маршрута используются актуальный автоматический коммерческий KRW/USD курс из Naver/Bithumb USDT/KRW с клиентской поправкой, доставка $4 900, комиссия 2%, SVH/декларант €150, услуги компании $300 и парковка 440 000 KRW. Значение KRW/USD 1397 — только ручной fallback профиля, не текущий автоматический курс. Сумма €400 из белорусского профиля и отдельные €40 за белорусское оформление не копируются в РФ: утилизационный сбор и таможенный сбор РФ уже входят отдельными строками TKS.

Для европейских автомобилей не переносить корейскую логистику/стоянку/курс автоматически. Взять из европейского белорусского расчёта только идентифицированные общие коммерческие строки и отдельно задать маршрут/источник цены. Если точных российских тарифов пока нет, разрешённый предварительный baseline хранить как версионируемый профиль с явной пометкой «оценка», чтобы позднее заменить без изменения формулы ТКС.

Проверка: текущий Supabase профиль `belarus-default` и таблица автоматического KRW курса прочитаны без записи. Профиль содержит KRW/USD fallback 1397, delivery 4900 USD, commission 2%, SVH/declarant 150 EUR, company service 300 USD; действующая pricing-context использует свежий сохранённый Naver/Bithumb USDT/KRW + клиентскую поправку. На проверенном snapshot raw rate был 1363, поправка −9, effective rate 1354 KRW/USD (timestamp 2026-11-07 06:02:53 UTC). Стоянка 440000 KRW подтверждена в коде. Европейские параметры взяты из действующего Europe→Belarus профиля (EC service 2.5%, translation 1.5%, delivery 2200 EUR, company service 1000 EUR). Белорусские обязательные сборы не перенесены; существующий белорусский калькулятор/профили не менялись. Контрольные арифметические примеры для KRW и EUR добавлены в отдельный baseline-файл; фиксированный KRW курс в примере помечен как fixture. Production DB и расчётный код не изменялись.

Критерий 100%: каждая коммерческая строка классифицирована (общая, Корея, Европа, РФ), имеет валюту и основание; государственные платежи не задвоены; курс ЦБ и коммерческий курс разделены в модели; baseline РФ сохранён отдельной версией с контрольными примерами.

## Checkpoint 4 — архитектура выбора страны и валюты

Статус: **ВЫПОЛНЕНО** (2026-11-07). Архитектура зафиксирована в [country-currency-switch-architecture.md](country-currency-switch-architecture.md).

1. Добавить глобальный выбор страны назначения Беларусь/Россия (не отдельный расчётный переключатель в каждой карточке).
2. Сохранять настройку между главной, каталогами и карточкой (URL-параметр для ссылок/шаринга + cookie/local preference для навигации; Беларусь — обратимое значение по умолчанию).
